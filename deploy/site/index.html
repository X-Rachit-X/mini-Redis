A Redis-compatible server, written from scratch in C++17.

It speaks the real Redis protocol, so the official Redis tools work with it unchanged. Open the live terminal and try it: you'll be typing into my own client, talking to my own server, running on this machine.

Commands to try

Copy a line, paste it into the terminal (Ctrl+Shift+V, or right-click → Paste), press Enter. Type help there for more.

Store and read a value

SET greeting "hello world"
GET greeting
→ OK, then "hello world"

Count things

INCR visits

Run it a few times. Every command runs on one thread, one after another, so no update is ever lost, even with many visitors at once.

Use a list as a queue

RPUSH jobs build test deploy
LPOP jobs
LRANGE jobs 0 -1
→ (integer) 3, "build", then the two left

Store an object as a hash

HSET user:1 name Ada lang C++
HGETALL user:1
→ field, value, field, value

Build a leaderboard

ZADD board 300 carol 100 alice 200 bob
ZRANGE board 0 -1 WITHSCORES
ZRANK board carol

Sorted by score. Behind it is a skip list that finds a member's rank without walking the whole set.

Make a key expire

SET otp 4821 EX 10
TTL otp
GET otp
→ wait 10 seconds before the GET: (nil)

Use the wrong type

GET jobs

Every key holds exactly one type, so this gives the same WRONGTYPE error real Redis does.

Everyone who opens the terminal shares one database, so you may see other visitors' keys, and they may change yours. Please don't store anything personal.

What's under the hood

The full design, tests and benchmarks are documented in the repository.

One thread, no locks

An epoll event loop serves every client from a single thread, the same model Redis uses. Every command is atomic.

A streaming protocol parser

Handles commands split across network packets and many commands sent at once (pipelining).

Skip-list sorted sets

Each link stores how many nodes it skips, so rank and range queries take O(log n).

Crash-safe persistence

An append-only log, replayed on startup. A half-written last entry is repaired, and compaction swaps files atomically.

Measured, not assumed

Benchmarked against real Redis with redis-benchmark. Memory per key cut from 5 KB to 175 B after measuring it.

Tested

Unit tests, randomized tests and end-to-end tests, all run under AddressSanitizer in CI.
